# Dashboard backend

Маленький сервер-посредник: хранит API-ключи в `.env` (никогда не в браузере),
стучится к вашим сервисам и отдаёт дашборду готовый JSON через `/api/overview`.

## Запуск

```
cd server
npm install
copy .env.example .env
npm start
```

Дашборд (`../index.html`) сам достучится до `http://localhost:8787/api/overview`
при открытии. Если сервер не запущен или источник не настроен — дашборд тихо
остаётся на демо-данных и показывает бейдж «Демо-данные» вместо «Есть живые
данные».

## Что нужно от вас, чтобы источник заработал

Ни один ключ вставлять в чат не нужно — впишите их прямо в `server/.env`
(этот файл не публикуется никуда, `.env.example` — просто шаблон имён переменных).

### YouTube (подписчики) — уже готово к подключению
1. console.cloud.google.com → создать проект → включить "YouTube Data API v3"
2. Credentials → API key
3. В `.env`: `YOUTUBE_API_KEY` и `YOUTUBE_CHANNEL_ID`

### Prodamus (деньги + продажи) — вебхуки, не запрос по требованию
У Продамус нет REST-эндпоинта «дай мне список заказов» — вместо этого он
сам шлёт POST-уведомление на наш URL при каждой оплате.
1. Личный кабинет Продамус → Настройки платёжной формы → добавить
   «url для уведомлений об оплате»: `<публичный адрес сервера>/webhooks/prodamus`
2. В `.env`: только `PRODAMUS_SECRET_KEY` (для проверки подписи уведомления)
3. Сервер копит пришедшие события в `store/prodamus-events.json` и считает
   из них сумму/количество продаж за период — смотри `store/prodamus-store.js`
   и обработчик `/webhooks/prodamus` в `server.js`.
4. Разбор полей уведомления (`sum`/`date`/…) — предположение по типовому
   формату таких сервисов; если после первого реального события суммы не
   сойдутся — смотрите `GET /webhooks/prodamus/debug`, там сырые данные
   последних 10 уведомлений, поправим извлечение полей.

### Точка / Тинькофф / Сбербанк (все движения по счетам)
Банковские API — самая долгая часть: обычно нужно зарегистрировать
приложение в личном кабинете разработчика банка и получить токен.
Раз доступ к API у вас уже есть для всех трёх — пришлите мне (не в общий
чат, а когда будете готовы вписать в `.env`) по каждому банку:
- базовый URL API
- путь эндпоинта выписки/операций по счёту
- как выглядит токен/авторизация (Bearer-токен предполагается по умолчанию)

Я специально не стал вписывать угаданные пути в код — банковские API
меняются и по-разному устроены, неверный путь только собьёт с толку.
Как только пришлёте точные эндпоинты — впишем их в `connectors/tochka.js`,
`connectors/tinkoff.js`, `connectors/sberbank.js` и в `.env`.

## Известное упрощение

Дельта «▲12.4% к пред. месяцу» на плитках сейчас всегда демонстрационная —
подсчёт реального изменения к прошлому месяцу ещё не реализован (нужно
запрашивать данные за два периода на каждый источник). Скажите, когда
дойдём до этого шага.
